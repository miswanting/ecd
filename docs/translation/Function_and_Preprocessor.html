函数与预处理指令

翻译自原文档：https://osdn.net/projects/emuera/wiki/exfunc

函数

@EVENTLOAD

在数据加载完成后立即调用。

由于它是事件函数，因此可以定义多个。

如果没有定义 @EVENTLOAD，则会转移到 @SHOW_SHOP（与 Eramaker 的行为相同）。

@TITLE_LOADGAME

在标准标题画面中选择读取时被调用。

通过定义 @TITLE_LOADGAME，标题画面也可以使用自定义的读取画面。

如果没有定义，则使用标准的读取画面。

在定义了 @SYSTEM_TITLE 的情况下，除非显式 CALL，否则 @TITLE_LOADGAME 不会被调用。

@SYSTEM_AUTOSAVE

在将要进行自动保存的时机被调用。

可以自行决定自动保存的内容。

如果没有定义，则使用标准的保存功能。

@SYSTEM_TITLE

在 csv 加载结束时被调用。

此外，通过 BEGIN TITLE 也会被调用。

通过定义 @SYSTEM_TITLE，可以使用自定义的标题画面。

如果没有定义，则使用标准的标题画面。

@CALLTRAINEND

在 CALLTRAIN 的自动执行结束后，由系统内部自动调用的函数。

请注意，它不是事件函数，不能多重定义。

自制函数中的参数指定

※1.54u 之前与 1.60 之后的规格不同！※

格式

函数侧：

@(函数名),(参数1),{(参数2)....}
参数若为数值则用 ARG(:0,1,2...)，若为字符串则用 ARGS(:0,1,2...)
函数中用 #DIM、#DIMS 定义的私有变量也可以指定为参数

调用侧：

CALL (函数名),(参数1),{(参数2)....}

参数可以使用数值表达式或字符串表达式。

把字符串字面量（常量）作为参数时，请用 "" 括起来。

把带格式的字符串字面量作为参数时，请写成 @"～～"。

除了 CALL 之外，JUMP、CALLFORM、TRYCALL 等也可以使用相同的格式。

函数侧可以指定任意数量的参数。

截至 ver1.808，如果函数侧与调用侧的型不同，无论是数值到字符串还是字符串到数值，都不会进行转换，而是直接出错。

如果想像 ver1.807 及更早版本那样，用数值调用字符串型参数，请修改配置设置改用自动补充 TOSTR，或使用 TOSTR 函数。

参数可以省略。省略时，若没有设置初始值，数值型参数会被赋值为 0，字符串型参数会被赋值为空字符串。

在被调用的函数侧，可以通过 ARG 和 ARGS 引用传入的值。

请注意，这基本上是值传递，因此即使改变 ARG 的内容，也不会改变传入方原本的变量等的值。

也可以把 ARG、ARGS，或者函数中用 #DIM、#DIMS 定义的私有变量以外的变量（如 A、STR）作为参数，但有一些限制。

截至 ver1.808，使用这些变量时不能设置初始值，也不能省略参数。

;定义
@FOOBAR, ARG:0, ARGS:0
  ～～
@HOGEHOGE, ARG:0, ARG:1, ARG:2
  ～～
;调用
;用变量指定
CALL FOOBAR, X , STR:0
;用常量指定
CALL FOOBAR, 123 , "あいう"
;用带格式的字符串指定
CALL FOOBAR, 123 , @"[{COUNT}] あいう"
;用表达式指定
CALL FOOBAR, X + 10, "あいう" * 10
;参数省略——全部
CALL FOOBAR
;参数省略——第 1 个参数
CALL FOOBAR, , "あいう"
;参数省略——第 2 个参数
CALL FOOBAR, 123
<会出错的例子>
;错误（参数过多）
CALL FOOBAR, X , STR:0, Y
;错误（参数型不符——试图把字符串赋给数值型的第 1 个参数）
CALL FOOBAR, "あいう", "かきく"
;错误（参数型不符——试图把数值赋给字符串型的第 2 个参数）
CALL FOOBAR, 123 , 456
<能运行但不推荐的做法>
;赋值目标可以不是 ARG、ARGS，但通常推荐使用 ARG
@FOOBAR, X, Y
;赋值目标也可以是可变的，但会降低可读性
@FOOBAR, ARG:X, ARG:Y
;可读性会降低
@FOOBAR, ARG:0, ARG:(ARG:0)

参数的初始值

可以为函数参数设置初始值。

设置初始值时，函数侧如下所示：

@(函数名),(参数1 = 初始值1),{(参数2 = 初始值2)....}
参数若为数值则用 ARG(:0,1,2...)，若为字符串则用 ARGS(:0,1,2...)，
或者使用函数中用 #DIM、#DIMS 定义的私有变量
指定除此之外的内容时，不能设置初始值。

可指定的初始值只能是常量和常数字符串，不能指定变量。

字符串的初始值请用 "" 括起来。

设置了初始值后，如果调用侧省略了参数，就会把初始值赋给该参数。

如果没有省略而正常调用函数，则会照常把传入的值赋给 ARG 和 ARGS。

;设置初始值（也可以只省略一部分）
@FUNCTION, ARGS:0 = "かきく", ARG:0 = 111, ARG:1, ARG:2 = 200
  ～～
;错误（初始值只能是常量和常数字符串）
@FOOBAR, ARG:0 = MASTER, ARG:1 = TARGET
;给 ARG、ARGS 以及函数中用 #DIM、#DIMS 定义的私有变量以外的参数设置初始值会被忽略
;因此无法按预期工作
@FOOBAR, X = 5, Y = 4

参数的引用传递

从 ver1.810 开始，通过把引用型变量作为形参，就可以实现参数的引用传递。

关于引用型变量的定义方法，请参阅引用型变量一节。

;<xxx.ERB>
@SYSTEM_TITLE
  A = 0
  CALL TEST(A)
  B = 1
  CALL TEST(B)
  PRINTFORML A == {A}
  PRINTFORML B == {B}
  WAIT

@TEST(HOGE)
  #DIM REF HOGE
  HOGE = 100
  RETURN

执行结果：

A == 100
B == 100

在上面的例子中，函数 TEST 的形参是引用型变量。

第一次调用 TEST 时，HOGE 会引用实参 A。

在函数 TEST 中执行 HOGE = 100，就会把 100 赋给引用目标变量 A，因此第一次 PRINTFORML 的结果为 100。

同样地，第二次调用 TEST 时会把 100 赋给变量 B，第二次 PRINTFORML 的结果也为 100。

属性

属性是决定函数规格和行为的预处理指令。

给函数书写以 # 开头的预处理指令时，必须紧跟在函数声明之下。

#ONLY

事件函数专用的属性。

如果存在指定了 #ONLY 的事件函数，则只有这一个会被执行，同名的其他事件函数不会被执行。

另外，即使存在多个指定了 #ONLY 的同名事件函数，被执行的也只有「最初的那一个」。

#FUNCTION

数值型表达式内函数的属性。

表达式内函数不能通过通常的 RETURN 结束，而必须用 RETURNF <数值表达式> 结束。

详情请参阅用户自定义表达式内函数。

#FUNCTIONS

字符串型表达式内函数的属性。

表达式内函数不能通过通常的 RETURN 结束，而必须用 RETURNF <字符串表达式> 结束。

详情请参阅用户自定义表达式内函数。

定义

定义是用于定义变量名称及其规格的预处理指令。

给函数书写以 # 开头的预处理指令时，必须紧跟在函数声明之下。

#LOCALSIZE <常数表达式> 与 #LOCALSSIZE <常数表达式>

这是为每个函数分别指定 LOCAL 和 LOCALS 元素数的预处理指令。

常数表达式的计算结果必须是大于 0 的整数；否则，或表达式中包含变量，或给出了无法解释的字符串时，都会被忽略。

被忽略或未使用该预处理指令时，会照常使用 VariableSize.csv 中的设置值。

如果对事件函数使用这个预处理指令，则会采用最先被执行的那个函数的设置（截至 ver1800）。

#DIM

用户自定义变量的声明。

在 ERB 的特定函数内使用时，可以定义只能在该函数内使用的数值型变量。详情请参阅用户自定义变量。

另外，在 ERH 中使用时，可以定义在所有函数间共享值的数值型变量。详情请参阅头文件（ERH）。

#DIMS

用户自定义变量的声明。

在 ERB 的特定函数内使用时，可以定义只能在该函数内使用的字符串型变量。详情请参阅用户自定义变量。

另外，在 ERH 中使用时，可以定义在所有函数间共享值的字符串型变量。详情请参阅头文件（ERH）。

#DEFINE

DEFINE 宏的声明。

在 ERH 中使用时，可以把所有 ERB 代码中的某个字符串替换为预先定义好的另一个字符串。详情请参阅头文件（ERH）。

代表特殊区块的行

这些是预处理指令行。

在书写它们的同一行中，不能紧跟着再书写指令、函数或注释等内容。

Eramaker 无法解释这些内容，因此根据情况编写代码时可能需要使用 ;!;。

[SKIPSTART] 与 [SKIPEND]

写在 [SKIPSTART] 到 [SKIPEND] 之间的行，Emuera 不会读取和执行。

当想要故意改变 Emuera 和 Eramaker 之间的行为时会用到它。

请用它来书写不希望 Emuera 执行的语句。

另外，与 ;!; 一起使用时，还可以书写不希望 Emuera 以外执行的语句。

详情请参阅常规一节。

[IF XXX] 与 [ELSEIF XXX] 与 [ELSE] 与 [ENDIF]

根据名为 XXX 的宏是否已定义，可以分支决定是否执行多行内容。

详情请参阅头文件（ERH）。

[IF_DEBUG] 与 [ENDIF]

写在 [IF_DEBUG] 到 [ENDIF] 之间的行，只在调试模式下执行。

非调试模式下，它会被视为注释行，不会被执行。

不过，DEBUG 系指令在非调试模式下原本就会被忽略，所以没有必要在行首加上 ;#;。

同样，调试变量在非调试模式下是空字符串或 0，因此不必担心出错。

关于调试模式的详情，请参阅调试模式。

[IF_NDEBUG] 与 [ENDIF]

写在 [IF_NDEBUG] 到 [ENDIF] 之间的行，只在非调试模式下执行。

调试模式下，它会被视为注释行，不会被执行。

判断与 [IF_DEBUG] 正好相反。

关于调试模式的详情，请参阅调试模式。
