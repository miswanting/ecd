# 发布与打包指南

## 前言

游戏做完了，怎么把它交给玩家？这一篇讲讲**打包、兼容与发布**的注意事项——这些事看起来琐碎，却直接决定玩家能不能顺利打开你的游戏。

::: warning 教程依赖

本教程假设您已完成[完整实战：打工养成](Case_Study)。

:::

## 一个典型的发布目录

发布时，玩家拿到的应该是一个可以直接运行的文件夹：

```
我的游戏/
 ├─ Emuera1824.exe      ← 引擎本体
 ├─ CSV/                ← 数据文件
 ├─ ERB/                ← 脚本
 ├─ resources/          ← 图片等资源（如果用到）
 └─ 说明.txt            ← 玩法 / 操作 / 许可说明
```

**不要**把下面这些一起打包：

- `emuera.config`（玩家自己的设置，不该被覆盖）；
- `sav/`、`global.sav`、`save*.sav`（存档）；
- `emuera.log`、`debug/`（调试产物）。

## 需要固定某些配置时

如果你确实需要某些配置对所有玩家生效（例如换行行为、字体），不要直接塞 `emuera.config`，而是用**强制配置**：

- `CSV/_default.config`：作为默认值，玩家仍可在设置里修改；
- `CSV/_fixed.config`：强制生效，玩家无法修改。

例如，依赖旧换行行为的脚本可以放一个 `_fixed.config`：

```
ボタンの途中で行を折りかえさない:YES
```

详见[强制配置项目](../../translation/Config)。

## 说明目标引擎

这是**最重要**的一条。不同引擎/改造版支持的特性不同：

- 如果只用到 Eramaker / Emuera 共通的功能，兼容性最好；
- 如果用了 Emuera 的扩展语法，请在说明里写明“需要 Emuera 及相应版本”；
- 如果用了某个改造版的专属功能（图片、动画、工具提示等），务必写清引擎名称与版本。

可以对照[兼容性矩阵](../../reference/Compatibility)与[版本特性索引](../../reference/Version_Index)自查。

## 脚本编码

- 脚本通常使用 **Shift-JIS** 编码；如果改成 UTF-8，请确认目标引擎支持；
- 存档编码可以在配置里选择（`セーブデータをUTF-8で保存する`、`セーブデータをバイナリ形式で保存する`）。**改变存档编码会影响与旧版本的兼容性**，发布前想清楚。

## 版本与更新

建议在游戏里维护一个版本号（`GameBase.csv` 的`バージョン`），并注意：

- 版本号也是存档校验的一部分，改动它可能让旧存档无法读取；
- 发布更新时，在说明里写清“是否需要重开”“存档是否兼容”。

## 许可与致谢

- 引擎（Emuera / Eramaker / 改造版）有自己的许可，请遵守并保留其说明文件；
- 如果使用了他人提供的素材、脚本、翻译，记得署名致谢；
- 本文档项目同样采用开源许可，欢迎在说明里附上链接。

## 发布前检查清单

- [ ] 把 `emuera.config`、`sav/`、日志排除在发布包外；
- [ ] 需要固定的设置改用 `_default.config` / `_fixed.config`；
- [ ] 说明里写清**目标引擎与版本**；
- [ ] 从零开始能正常进入游戏；
- [ ] 存档、读档都正常；
- [ ] 没有会让玩家卡死的死循环；
- [ ] 报错信息玩家能看懂；
- [ ] 许可与致谢齐全。
